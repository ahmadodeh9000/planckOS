# Interrupts: GDT, IDT, PIC and system calls

The CPU-level setup lives in `src/arch/`.

## System calls — `arch/syscall.c`

**What it does.** Lets code call into the kernel with `int 0x80`, which is
how future user-mode programs will ask for services.

**How it works.** IDT entry 128 (`0x80`) is installed with DPL 3
(`type_attributes = 0xEE`), so ring-3 code is allowed to trigger it. The
assembly stub saves all registers into a `registers_t` and calls
`isr_handler`, which passes vector 128 to `syscall_handler`. Arguments go in
registers:

| Register | Meaning |
|----------|---------|
| `eax` | System call number (in), return value (out) |
| `ebx` | First argument |

| Number | Name | Effect |
|--------|------|--------|
| 0 | `SYS_PRINT` | Print the string at `ebx`. |
| 1 | `SYS_MALLOC` | `eax = kmalloc(ebx)`. |
| 2 | `SYS_FREE` | `kfree(ebx)`. |
| 3 | `SYS_EXIT` | Print "Process ended" and halt. |
| 4 | `SYS_PRINT_HEX` | Print `ebx` as hex. |

Return values work by writing to `regs->eax`. The stub's `popa` loads the
saved registers back, so the caller sees the new `eax`.

**Extending it.** Add a `SYS_` number in `syscall.h` and a `case` in
`syscall_handler`. Once user mode exists, check every pointer argument
before using it.

**Known limits.** Everything still runs in ring 0, so no call is protected
yet. `SYS_EXIT` halts the whole machine.

## GDT and TSS — `arch/gdt.c`

**What it does.** Sets up the segment descriptors the CPU needs in protected
mode, plus a Task State Segment (TSS) for future ring changes.

**How it works.** planckOS uses a flat memory model. Every code and data
segment has base 0 and limit 4 GB, so segmentation does nothing and paging
does the real work.

| Index | Selector | Descriptor |
|-------|----------|------------|
| 0 | `0x00` | Null (required) |
| 1 | `0x08` | Kernel code (ring 0) |
| 2 | `0x10` | Kernel data (ring 0) |
| 3 | `0x18` | User code (ring 3, selector `0x1B` with RPL 3) |
| 4 | `0x20` | User data (ring 3, selector `0x23`) |
| 5 | `0x28` | TSS |

`gdt_flush` (in `gdt.s`) runs `lgdt`, reloads the data segment registers with
`0x10`, and does a far jump to `0x08:.flush` to reload `cs`.

A descriptor's **limit** is the offset of the *last* valid byte, so the TSS
limit is `sizeof(tss) - 1`. The TSS's `esp0`/`ss0` fields tell the CPU which
stack to switch to when an interrupt arrives in ring 3. `esp0` is still 0
(marked TODO), which is harmless only while everything runs in ring 0.

**Key functions.** `gdt_init()`, called first in `cpu_init`.

**Extending it.** For user mode, set `esp0` to the top of a kernel stack,
load the TSS with `ltr` (selector `0x2B`), then enter ring 3 with an
`iret` frame that uses the user selectors `0x1B`/`0x23`. See `ROADMAP.md`.

**Known limits.** The TSS is described but not loaded yet.

## IDT and PIC — `arch/idt.c`, `arch/idt.s`

**What it does.** Tells the CPU where to jump for each of the 256 interrupt
vectors, and routes hardware IRQs to driver handlers.

**How it works.**

| Vectors | Source | Handled by |
|---------|--------|------------|
| 0-31 | CPU exceptions (divide error, page fault, ...) | `isr_handler`: logs to serial, prints the name and halts |
| 32-47 | Hardware IRQ 0-15 via the PICs | `irq_handler`: calls the registered driver handler, then sends EOI |
| 128 (`0x80`) | `int 0x80` system calls | `isr_handler` → `syscall_handler` |

*Stubs.* Each vector has a tiny assembly stub in `idt.s`, generated by the
`ISR_NOERRCODE`, `ISR_ERRCODE` and `IRQ` macros. Some exceptions make the
CPU push an error code and most don't. Stubs for the second kind push a
dummy 0, so the stack always looks the same. The shared `COMMON_STUB` saves
the general registers (`pusha`) and segment registers, switches to the
kernel data segment and calls C with a pointer to that saved state, a
`registers_t`.

*PIC remapping.* The two 8259 PICs start out delivering IRQ 0-7 on vectors
8-15, the same numbers as CPU exceptions (IRQ0, the timer, would look like a
double fault). `pic_remap()` sends the four initialization words (ICW1-4) to
both chips: master at vector 32, slave at 40, slave cascaded on IRQ 2, 8086
mode. It then unmasks all lines.

*End of interrupt.* A PIC delivers no further interrupts on a line until it
gets an EOI (`0x20`). IRQs 8-15 pass through both chips, so they need an EOI
on the slave and the master.

**Key functions.**

| Function | Purpose |
|----------|---------|
| `idt_init()` | Remap the PICs, fill the IDT, `lidt`. |
| `irq_install_handler(irq, fn)` | Run `fn(regs)` whenever IRQ `irq` fires. |

**Extending it.** For a new device IRQ, write a handler and call
`irq_install_handler`. The handler should only read the device and record
what happened (a counter, a queue entry). It runs with interrupts disabled,
so don't draw or do slow work in it.

**Known limits.** No spurious-IRQ (IRQ 7/15) detection. Exceptions always
halt, so page faults can't be handled yet.
